Masked Is Not Harmless: Certified Gate-Level Fault
Vulnerability Analysis with LLM Agents That
Propose and Engines That Decide
Ali Roshani, Mohsen Ansari, and Mohammad T. Manzuri Shalmani

Abstract—Gate-level fault injection labels every fault as silent
data corruption (SDC), detected unrecoverable error (DUE),
or masked. The masked label mixes faults that are harmless
with faults that the workload never exercised, and no current
tool says how large the second group is. We present GateScan,
a framework that reports vulnerability as a certified bracket
instead of a point estimate. The lower end counts faults with
a replay-confirmed detection, the upper end removes faults
proven harmless by structural or formal arguments, and every
sampled quantity carries an interval with exact coverage. Large
language model (LLM) agents narrow the bracket by writing
workloads and per-fault trigger sequences, but they only propose:
a deterministic core computes every verdict, so a wrong agent
can widen the bracket and can never make it false. An elevenclass taxonomy refines SDC/DUE/masked by the evidence behind
each verdict. On the three ShadowFI benchmarks, 13% to 55%
of the faults that the three-class view reports as masked are
vulnerabilities proven by replayed witnesses, and the agents raise
the certified lower bound of the tensor core unit from 72.5% to
87.5%. On twenty ITC’99 circuits of up to 105k cells, the bracket
shows where random workloads fail; we also report the designs
on which the agents did not help.
Index Terms—Fault injection, vulnerability analysis, stuck-at
faults, soft errors, formal verification, statistical fault injection,
large language models, LLM agents, functional safety.

I. I NTRODUCTION
HEN a fault-injection campaign reports that a fault is
masked, what do we actually know? Safety standards
such as ISO 26262 [1] and architectural vulnerability factor
(AVF) analyses [2] turn such labels into diagnostic-coverage
figures and failure rates, so the answer matters. Since the
FARM framework [3], a campaign has been defined by its
faults, its activation (the workload and the injection time), its
readouts, and its measures. Modern open-source tools such as
ShadowFI [4] inject millions of gate-level faults through netlist
saboteurs and classify each outcome as silent data corruption
(SDC), detected unrecoverable error (DUE), or masked.
The masked class hides two very different situations. A fault
may be harmless: no input sequence can ever make it visible.
Or the workload may simply never have activated it, or never
propagated its effect to an output. The first fault is irrelevant
for safety; the second is a vulnerability that the campaign
missed. Every tool we surveyed takes the workload from the

This paper argues that gate-level vulnerability should be
reported as a bracket whose two ends are backed by different
kinds of evidence. The lower end counts faults for which a
concrete input sequence, replayed in two simulators, produces
an output error. The upper end removes faults proven harmless,
either structurally or by a formal proof. Everything in between
is undecided and is said to be so. The bracket is always correct;
its width measures how much the evidence still lacks.
Narrowing the bracket needs better workloads, and writing
workloads for an unfamiliar design is exactly the expert task
that large language models (LLMs) have begun to automate
for RTL code and testbenches [5]–[7]. An LLM, however, is
not a sound oracle. Our design principle is therefore a strict
division of labor: the LLM proposes, the deterministic core
decides. Agents write workloads, per-fault trigger sequences,
and application-level tolerances as data; a deterministic core
turns this data into verdicts, and every number in a report is
a function of the netlist, the workloads, the seeds, and solver
answers only. A wrong agent can make the bracket wider; it
can never make it false.
We implement this principle in GateScan (Fig. 1), an
open framework built on Yosys [8], Verilator [9], Icarus
Verilog [10], and ABC [11], and we use Claude Opus 5.5 as
the LLM in all experiments. The contributions are as follows.
1) A certified vulnerability bracket with exact, designaware statistics (Clopper–Pearson for independent
pairs, hypergeometric for samples without replacement,
Hoeffding–Serfling for clustered samples) and an escape
certificate that bounds the share of vulnerable faults
among the undecided ones (Sections III and V).
2) An eleven-class taxonomy that keeps SDC, DUE, and
masked but splits them by evidence: escaped vulnerabilities, delayed SDC, latent, healed, benign latent, proven
ineffective, and unknown (Section III).
3) An agent layer of five LLM roles, including a per-fault
trigger agent that receives an activation/propagation
diagnosis of each undecided fault, with a soundness
argument that no agent output can change a verdict
(Sections IV and V).
4) An evaluation on the three ShadowFI benchmarks and
twenty ITC’99 circuits [12] that shows what the threeclass view hides, how far the agents close the gap, and

A. Fault Models, Test, and Fault Injection
Gate-level analysis inherits its fault models from manufacturing test: single stuck-at faults on stems and branches,
and transient faults (single-event transients and upsets) for
radiation effects [13]–[15]. Test generation answers a related
question to ours: whether some input sequence detects a fault.
Combinational ATPG is complete [16], [17], sequential ATPG
is hard in general [18], [19] and is solved in practice by deterministic and genetic search [20], [21], and model checking
proves faults untestable through bounded or inductive reasoning [11], [22]–[24]. Fault injection asks a different question:
what happens under the intended workload. Simulation-based
injectors use saboteurs, mutants, or simulator commands [25]–
[29], and emulation moves the same idea to FPGAs [30]–[32].
FARM [3] gives the vocabulary used here: faults, activation,
readouts, and measures.
B. Statistics of Fault-Injection Campaigns
Powell, Arlat, and co-workers showed that coverage is a
property of the joint fault and activation space and gave
stratified estimators with confidence limits [33]–[35]. The
sample-size formula of Leveugle et al. [36] is the most used in
practice; it treats the fault location as the only random factor
and relies on a normal approximation. Exact binomial intervals [37] are standard elsewhere, but we found no injection
tool that reports intervals whose coverage depends on its actual
sampling design.

C. Recent Frameworks and Learning-Based Methods
ShadowFI [4] inserts Yosys-based saboteurs with a scanconfigured controller and runs campaigns on HPC simulators or on an FPGA cluster; on four accelerators it reports
SDC rates of about 72%–92% for stuck-at faults, with no
interval and no latent class, and the workload is a user
test application. RADSAFiE [38] inserts LUT-based injection
cells into FPGA netlists. Geier et al. [39] accelerate RTL
injection with checkpoints and a masking check and observe
that 46%–97% of experiments end neither in SDC nor in
DUE, which quantifies the latent problem. On the learning
side, RIFT [40] uses reinforcement learning to choose fault
locations in neural-network weights, FT-Pilot [41] uses a graph
network and an LLM to harden RTL with labels from injection
under a hand-written testbench, and graph or neural predictors
estimate flip-flop criticality from injection data [42]–[44].
LLM testbench generators optimize functional correctness or
code coverage [6], [7], [45], [46], not fault detection.

B. The Bracket
Partition the stuck-at faults into three sets. D holds faults
with a definite detection under some workload or a replayconfirmed witness. R holds faults proven unobservable, structurally or by a formal proof. U = F \ (D ∪ R) holds every
other fault, including every fault that the formal step did not
examine. Let V be the share of faults that some input sequence
from reset can expose.
Definition
 1 (Vulnerability bracket). The bracket of a campaign is |D|/|F|, (|D| + |U|)/|F| .
Theorem 2 in Section V shows that V always lies inside the
bracket. The lower end is what a classical campaign calls its
SDC plus DUE rate, but restricted to definite detections; the
upper end is what is left after removing proven harmless faults.
When faults are sampled, both ends carry exact intervals for
the population. The width |U|/|F | is the honest measure of
what the evidence lacks, and every component of GateScan
exists either to move faults out of U or to bound how many
of them are vulnerable.
For the faults that stay in U, GateScan draws a uniform
sample without replacement and asks the formal oracle about
each one. A fault with a replayed witness is a proven escape;
a solver timeout is counted as an escape. The hypergeometric
interval over the sample gives the escape certificate: an upper
confidence limit on the share of vulnerable faults among the
undecided ones. It answers the question of the introduction in
numbers.

Let N be the flat gate-level netlist synthesized from the
RTL, with state s, inputs u, observed outputs y, and one clock.
The fault universe F holds single stuck-at faults (SA0 and SA1
on stems and primary inputs) and single-event upsets (SEU,
one per storage bit); each experiment has exactly one fault. A
workload W is an input sequence u0 , . . . , uH−1 whose first
r cycles are the reset, with injection cycles T ⊆ [r, H). An
experiment (f, τ ) simulates N with fault f active from cycle
τ (a stuck-at fault stays active; an SEU inverts one bit until
its next capture) and compares it with the fault-free run. Its
verdict is detected if some output differs, hang if a liveness
output fails to re-assert, latent if no output differs but the final
state does, masked if neither differs, and untestable-structural
if no structural path leads from the fault site to an output. An
engine failure is an error and is never counted as masked.

C. An Evidence-Based Taxonomy
The bracket needs every experiment to say which kind of
evidence stands behind it. Fig. 2 shows the eleven classes,
grouped in four families and ordered by severity. Family F
holds faults that corrupted an output: DUE (a hang or a
declared alarm output), SDC, and TOL (an output differed
but every application metric stayed within the tolerance of
the interpreter agent, for example two units in the last place).
Family L holds latent errors: DLY (a delayed SDC that
surfaced during the follow-up) and LAT (still corrupted, fate
unknown). Family E holds faults that looked masked but
have more evidence: ESC (an escaped vulnerability with a
replayed witness from the formal oracle or the trigger agent)
and UNK (no verdict). Family M holds MSK (masked under
the workload, nothing more is known), HEAL (a transient
corruption that returned to the golden state), BEN (a latent
error proven unable to reach an output), and INE (proven
ineffective for every input).
A fault receives the most severe class over all its workloads.
The mapping back to SDC/DUE/masked is fixed, so every
GateScan report also contains the three-class view of the
same faults, and the two can be compared fault by fault
(Section VI). Only F, DLY, and ESC are proven vulnerable,
and only HEAL, BEN, and INE are proven harmless; MSK,
LAT, and UNK carry no proof either way. The single most
important difference from the three-class view is therefore that
masked becomes four classes with very different meanings:
ESC, MSK, BEN or HEAL, and INE.
IV. G ATE S CAN : AGENTS P ROPOSE , THE C ORE D ECIDES
Fig. 1 shows the two layers of GateScan. The deterministic
core turns a netlist, a fault set, and workloads into verdicts,

IEEE TRANSACTIONS ON COMPUTER-AIDED DESIGN OF INTEGRATED CIRCUITS AND SYSTEMS, VOL. XX, NO. X, MONTH 2026

bounds, and intervals. The agent layer reads what the core
reports and returns proposals as data. A proposal enters the
core only through a validation gate, and it can influence only
which experiments are run, never how they are judged.
A. The Deterministic Core
Synthesis and fault universe. Yosys synthesizes Verilog
or VHDL (through GHDL) to a generic-cell netlist with
redundancy preservation, so that registers written in the RTL
are not merged; an audit compares RTL and netlist storage bits
and warns when they differ. The fault universe is collapsed by
structural equivalence, and faults with no path to an observed
output are marked untestable-structural. For a campaign restricted to a scope (a set of module instances), only the cone of
influence of the scope is simulated, which keeps every verdict
and divergence cycle unchanged (Theorem 7).
Instrumentation. Each fault receives exactly one hook and
each hook exactly one fault, which a bijection gate checks. A
linear-time structural argument, and a SAT equivalence check
for small designs, show that the instrumented netlist equals
the original one when injection is off; every run also replays
the golden trace with injection off and compares it bit for bit.
Simulation and follow-up. Verilator executes the campaign
in parallel shards; Icarus Verilog, a four-valued simulator, is
the reference engine for golden traces, differential checks, and
witness replay. With both engines, only definite (0 versus 1)
detections count; a detection seen only through an unknown
value is reported as UNK. A latent run is continued by
replaying the workload without a new reset, which decides
whether the error surfaces, heals, or persists.
Formal oracle. Undecided faults are sampled uniformly
without replacement and each sampled fault is encoded as a
miter between the fault-free and the faulty netlist under free
inputs. ABC [11] (dprove) or Yosys induction either proves
the fault untestable, returns a counterexample, or runs out of
time. A counterexample becomes an ordinary workload and
counts only after it detects the fault in both simulators. Proofs
are trusted; witnesses are not.
Statistics and report. Every share comes with the exact
interval of its sampling design (Section V). The report contains
the bracket, the escape certificate, the eleven classes and the
three-class view, SEU AVF bounds, per-region and per-register
breakdowns, and the provenance of every input.
B. The Agent Layer
Five LLM roles share one interface: a prompt built from
the core’s data, a JSON answer, and a validator. The analyzer
reads the port list, hierarchy, clocks, resets, and an RTL
excerpt, and returns the role of each port (data, control,
handshake) and the operating modes of the design. The scenario agent writes workloads in a small declarative language
(phases, per-port streams of random, constant, or explicit
values); each workload must compile against the design. The
critic checks a workload against the analyzer’s facts and
the last campaign report and may request a revision. The
interpreter writes an application metric (for example, outputs
decoded as IEEE-754 numbers with a tolerance in units in

4

the last place) and explanations of the observed outcomes; the
metric can only move an SDC to TOL, and each explanation
is checked against the measured fates. The trigger agent is
described next.
Every exchange is logged with the model identity, the
prompt and response hashes, the temperature, and the token
counts. In this paper all roles were played by Claude Opus 5.5
through a file-based exchange: the core writes a prompt, the
model writes the response, and the core validates it.
C. The Per-Fault Trigger Loop
Workload agents reason about the design as a whole.
Some faults, however, stay undecided because of one specific
condition, and a design-level workload rarely produces it. The
trigger loop targets them directly. A probe build of the netlist
records, for each undecided stuck-at-v fault, the value of its
site during the workload. If the site never takes the value v̄,
the fault was never activated; otherwise it was activated but
its effect never propagated to an output. The trigger agent
receives this diagnosis, grouped by module and signal, together
with the design facts, and writes workloads that aim at the
missing condition: rare operand combinations for activation,
or sequences that keep a corrupted value alive until it is read
for propagation. The core then runs every undecided fault
under the new workloads, and each new detection enters D
only through the same definite, replayed path as any other
detection. The loop stops when a round no longer shrinks U
appreciably.
V. G UARANTEES
An LLM inside a safety analysis is acceptable only if the
analysis remains correct when the LLM is wrong. This section
states what GateScan guarantees, under which assumptions,
and how each assumption is enforced; proofs are in Appendix A.
A. Assumptions
GateScan distinguishes checked assumptions, which a gate
verifies in every campaign and which stop the campaign
when they fail, from stated assumptions, which appear in
every report. Checked: (A2) the instrumented netlist with
injection off equals the original; (A3) hooks and faults are
in bijection; (A4) the engines follow the simulation protocol,
verified by Verilator–Icarus golden-trace equality, differential
verdicts, and two-engine replay of every witness. Stated: (A1)
the netlist behaves like the RTL on its ports, supported by the
storage-bit audit; (A5) one fault per experiment; (A6) solver
proofs of untestability are sound, validated against exhaustive
simulation; (A8) the workload is a legal behavior of the
environment, while formal witnesses may use inputs that the
real environment never produces.

Theorem 2 (Bracket). |D|/|F| ≤ V ≤ (|D| + |U |)/|F|.

We ask three questions. RQ1: what does the three-class view
hide on designs where published results exist? RQ2: do LLM
agents narrow the bracket, and when do they fail? RQ3: how
does the approach scale, and what does it cost?

Theorem 3 (Independence from the LLM). Every verdict,
class, bound, and interval is a deterministic function of the
netlist, the fault set, the workloads, the seeds, and the solver
answers. An arbitrarily wrong agent can only lower coverage, which widens the bracket, or loosen a tolerance, which
changes only the application-level AVF reported next to the
raw bounds.
Theorem 4 (Monotonicity). For workload sets W ⊆ W ′ ,
D(W) ⊆ D(W ′ ). Because every agent flow keeps the given
or random workload, agents can never lower the lower end
of the bracket.
Theorem 5 (SEU AVF bounds). Let AVF∞ be the share of
SEU experiments whose error ever reaches an output when
the workload continues. Then the share detected within the
horizon is at most the share detected within the follow-up,
which is at most AVF∞ , which is at most the share not shown
to be masked.
Theorem 6 (Exact coverage). Each reported interval covers
the true share with probability at least 0.95 for every value of
that share: exact for a census; Clopper–Pearson [37] for independent fault–cycle pairs; the inverted hypergeometric test for
faults sampled without replacement; Hoeffding–Serfling [48],
[49] for samples without replacement with several cycles per
fault. The escape certificate is a hypergeometric interval over
the residue, with every unknown counted as an escape.
Theorem 7 (Exact cone reduction). Simulating only the cone
of influence of a scope gives, for every fault of the scope
and every input sequence, the same verdict and the same first
divergence cycle as the full netlist.
Theorem 3 is the formal content of the slogan in the title.
The agents can make the analysis weaker, never wrong; how
much stronger they make it is an empirical question, answered
in Section VI.
C. Validation of the Core
The theorems hold if the implementation does what the
proofs assume, so the core was tested against independent
references. On a catalog of 15 circuits, all 165 campaign gates
passed, and 1,834 experiments run in both engines gave no
verdict disagreement (104 detections depended on unknown
values and were classified UNK). On four combinational
designs, the formal oracle agreed with exhaustive simulation
on every fault. The follow-up equals a plain run on the
extended workload on all 22 design and workload pairs. The
hypergeometric interval reaches coverage of at least 0.95
for all 41 population counts of an exhaustive check, and
the Clopper–Pearson intervals reached 0.96–1.0 in calibration
studies where the Wald interval reached only 0.90–0.947.

VI. E VALUATION

A. Setup
All campaigns ran on one workstation with 16 hardware
threads and a Linux virtual machine limited to 11 GB of
memory, with Yosys 0.33, Verilator 5.020, Icarus Verilog 12.0,
and ABC from Yosys. The ShadowFI benchmarks [4] are the
two special function units (SFUv1, SFUv2) and the 4×4 tensor
core unit (TCU) from its public repository, each with its own
test application (140,062 operations for SFUv1, 4,096 matrix
products for TCU, and 880,083 vectors for SFUv2). The fourth
benchmark, the stereo vision core, could not be compiled:
Verilator exceeded the 11 GB limit. Each campaign targets
a scope: the squaring unit and exception logic of SFUv1,
one floating-point adder of the TCU dot-product unit, and
the 24 arithmetic submodules of SFUv2. We sampled 3,000
stuck-at faults without replacement in SFUv1 and TCU and
simulated all 2,720 of SFUv2. The formal oracle examined
a uniform sample of 60 undecided faults per design with a
60 s budget per fault. SEU campaigns used 2,450 independent
fault–cycle pairs. The ITC’99 circuits [12] used a uniform
random workload of 2,000 cycles, a census of the faults, except
for b17, b18, b19, and b22, where 2,450 faults were sampled
without replacement; the formal oracle examined up to 100
undecided faults per circuit.
B. RQ1: What the Three-Class View Hides
Table II and Fig. 3 compare the two views of the same
faults. The SDC rates are close to the published ones (94.3%
versus 92%, 72.3% versus 72%, 86.4% versus 80%). They
are not the same estimand, because ShadowFI reports wholedesign rates read from bar charts and we report scoped rates
with exact intervals; we therefore use them only as a sanity
check.
The difference lies in the masked class. Of the 171, 831, and
369 faults that the three-class view calls masked, 70 (41%),
457 (55%), and 48 (13%) are ESC: a witness, replayed in both
simulators, makes each of them corrupt an output. On SFUv1
and SFUv2 the witnesses come from the formal oracle alone,
from a sample of 60 representatives; on TCU, six come from
the oracle and the rest from the trigger agent (RQ2). Only
seven faults, all in SFUv1, were proven ineffective. The rest of
the masked class stays MSK, which a report must not read as
harmless. The three-class view also hides six latent errors and
28 detections that were visible only through unknown values in
TCU. For the SFUv1 outputs, the interpreter agent’s tolerance
of two units in the last place moves 569 SDC faults to TOL, so
the application-level AVF is about 75% while the raw failure
rate is 94%; both are reported.

D. RQ3: Scale and Cost
Fig. 7 shows the brackets of twenty ITC’99 circuits, from
39 to 104,873 cells and from 82 to 209,838 faults; Table III in
Appendix B lists all numbers. On small circuits the bracket is
closed or narrow, and the formal oracle does much of the work:
on b09 it turned 81.5% detection into an exact 98.0%, and on
b02, b03, b06, and b10 the vulnerability is known exactly. On
the large circuits, random workloads detect 1.5%–13.7% of
the faults while the brackets reach up to 97%–100%, and the
oracle returned no answer for any of the 100 sampled faults
of b18 and b19 within the budget. A point estimate of 3% for
b18 would be read as “the circuit is robust”; the bracket [3.2,
99.6] says that the campaign knows almost nothing.
GateScan is slower per fault than ShadowFI on two of the
three designs (Table II): 25.6 s against 1.4 s on TCU and 42.6 s
against 16 s on SFUv2, on one core, while it is faster on SFUv1
(0.78 s against 4.7 s). The comparison is not like for like: our
SFUv2 workload is almost nine times longer than ShadowFI’s
100,000 operations, and our per-fault time includes the twoengine checks, the follow-up of latent runs, and the formal
step. With 16 threads the wall-clock time per fault is 0.11,
3.6, and 5.4 s; campaigns are independent per fault, so the
same shards could run on a cluster or on the FPGA back end

2,450 faults, took 3.4 h.
VII. D ISCUSSION AND L IMITATIONS
What the agents contribute. The agents never decide anything, and their value is measured only by how much they
shrink U. That value was large where a short, legal, wellordered stimulus is what the design needs (b12, b13, SFUv2,
and the per-fault triggers on TCU), and zero where the agent’s

7

model of the design was wrong (b15–b18). The second case
is the reason for the architecture: a plausible but wrong
hypothesis produced a slightly weaker workload, and nothing
in the report became false. A per-fault trigger round on the
80386 subsets, as on TCU, is the natural next step.
Formal scaling. The oracle decides most sampled faults on
small and medium designs but almost none on b18, b19, and
the TCU adder within 60 s. Longer budgets, cone-restricted
miters, and property-directed reachability [24] would help; until then, the escape certificate on large designs is conservative,
because every timeout is counted as an escape.
Validity. The guarantees rest on stated assumptions: synthesis fidelity, sound solver proofs, a single fault per experiment,
and single-clock designs. Formal witnesses may use inputs
that the real environment never produces, so an ESC fault is
vulnerable structurally, not necessarily in operation; reports
keep the two apart. Our netlists use generic cells, and stuck-at
coverage over-estimates defect coverage [47]. The ShadowFI
comparison uses scoped campaigns, and one benchmark could
not be compiled within our memory limit.
The LLM. All agent roles were played by one model, Claude
Opus 5.5, in an interactive file exchange. Theorem 3 makes
the correctness of the results independent of this choice, but
the size of the gains is not: another model, or the same
model at a different temperature, may write better or worse
workloads. Every prompt, response, and resulting workload is
archived with its hash so that the gains can be reproduced or
challenged.
VIII. C ONCLUSION
A fault that a campaign calls masked may be harmless, or it
may be a vulnerability the workload never reached. GateScan
replaces the single SDC rate with a certified bracket that keeps
these cases apart, an eleven-class taxonomy that names the
evidence behind each verdict, and exact intervals for every
sampled share. LLM agents write workloads and per-fault
triggers that shrink the bracket, while a deterministic core
keeps every number independent of them. On the ShadowFI
benchmarks, 13% to 55% of the faults that the three-class view
calls masked are proven vulnerabilities, and the trigger agent
raised the certified lower bound of the tensor core adder from
72.5% to 87.5%. On ITC’99, the bracket shows which results
can be trusted and which cannot. The open problems are the
formal oracle on large designs and agents for processor-like
designs, where the first hypothesis of our agent was wrong.
